# Align, don't zero

Code and results for

> **Align, don't zero: a reference-scaled rule for cross-session mean correction in EEG decoding**

This repository contains the analysis pipeline, the independent re-implementation used for
reproduction, the feature builder for BCI-IV-2b, and the raw text output of every number
reported in the paper. Figures 1 and 2 are generated by the pipeline.

---

## What the paper claims, and where each claim is computed

| Claim | Where |
|---|---|
| Zeroing to the target mean can collapse decoding to chance; aligning to the training mean does not | `src/paper_numbers.py` |
| The damage is predicted by `z_pool`, the training mean in feature SDs | `src/paper_numbers.py` |
| The relation is causal, not correlational (intervention on `c`, with a built-in invariance check) | `src/paper_numbers.py` |
| Alignment closes the cross-day gap to within a few points of the within-session ceiling | `src/paper_numbers.py` |
| Shrinkage matters only when `E` is small; `E/(1+E)` beats full subtraction there | `src/paper_numbers.py` |
| `E` and `w` must be clipped at zero (5.0 % of raw estimates are negative) | `src/paper_numbers.py` |
| All of the above reproduce under an independent implementation and four seeds | `src/reproduce.py` |

`src/reproduce.py` shares no feature-extraction or evaluation code with `src/paper_numbers.py`
on purpose. It re-derives log band power, Euclidean-aligned log power, tangent-space features,
CSP log variance and balanced accuracy from scratch, and re-runs seven pre-registered claims
under four random seeds. Claim C8 (mediation) is expected to **fail**; the paper states that
mediation is not supported, so a pass there would indicate an over-conservative manuscript
rather than a better result.

## Data

Both datasets are public and are **not** included here.

**BCI Competition IV 2a** — nine subjects, four motor-imagery classes, 22 EEG channels.
Download `A01T.mat` … `A09T.mat` and `A01E.mat` … `A09E.mat` from
<https://www.bbci.de/competition/iv/#dataset1> into one directory:

```
$BSPC_DATA/BCICIV-2a-mat/A01T.mat
$BSPC_DATA/BCICIV-2a-mat/A01E.mat
...
```

**BCI Competition IV 2b** — nine subjects, two motor-imagery classes, three bipolar channels.
Download the 45 `.gdf` files (`B0101T.gdf` … `B0905E.gdf`) from
<https://www.bbci.de/competition/iv/#dataset2>:

```
$BSPC_DATA/BCICIV-2b/B0101T.gdf
...
```

Only the 27 screening sessions (`T`) carry labels; the 18 feedback sessions (`E`) do not and are
excluded. That leaves three labelled sessions per subject on three distinct dates, giving 27
cross-day pairs.

## Running it

Python 3.7 was used; nothing newer is required.

```
numpy==1.21.6  scipy==1.7.3  scikit-learn==1.0.2  matplotlib==3.5.3  mne==1.3.1
```

`mne` is needed only to read the GDF headers in step 1.

**Step 0 — point the scripts at your data.** Three optional environment variables:

| Variable | Default | Meaning |
|---|---|---|
| `BSPC_DATA` | `E:\data` | directory containing `BCICIV-2a-mat/` and `BCICIV-2b/` |
| `BSPC_CACHE` | `<repo>/features/cache_2b` | where the 2b feature cache lives |
| `BSPC_OUT` | `<repo>/results` | where outputs are written |

**Step 1 — build the 2b feature cache** (skip if you supply `features/cache_2b/` yourself):

```bash
python src/make_features_2b.py
```

Reads the GDF headers for recording timestamps, extracts 0.5–3.5 s after cue, band-passes
8–30 Hz, and writes one `.npz` per session. About two minutes.

**Step 2 — compute every number in the paper and both figures:**

```bash
python src/paper_numbers.py          # ~3 min
```

**Step 3 — reproduce independently:**

```bash
python src/reproduce.py              # ~2 min, four seeds
```

Both scripts write plain text. Compare against `results/`.

## Two implementation details worth knowing before you re-use this code

**`E` is clipped at zero.** The excess energy is `E = D_true / D_noise` with
`D_true = max(||δ̂||² − D_noise, 0)`. The unclipped difference is negative whenever the estimated
offset is smaller than its own sampling noise, which happens in 5.0 % of our 576 estimates
(minimum `E = −0.98`). Without the clip, `w = E/(1+E)` becomes negative — down to `−53` — and the
correction pushes the target *away* from the training distribution. The paper states the clip;
this is the code that implements it.

**Euclidean alignment must be applied to the raw signal, not to the covariance matrix.** Applying
the whitening matrix once on the channel axis and then taking log band power is what the name
means. An earlier version of this code applied it to covariance elements, which silently produced
`NaN` on 3-channel data and dropped one of four representations for BCI-IV-2b (81 cells instead of
108). The corrected version gives 4 representations × 27 pairs = 108 cells for that dataset.
